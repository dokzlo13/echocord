# Current state

The multiple-room release is delivered as a manually testable Windows app. Up to eight selected application process trees/recording inputs feed one native mix and four total destinations: Discord rooms in different servers under the existing bot, and at most three explicit Windows playback devices. Each output has independent start/cancel/stop, gain, mute, fault and session-fenced telemetry. One configured or retiring room reserves each server. New and restored outputs stay idle; source changes and ordinary output failures preserve their peers.

The native design uses a persistent tokenless audio worker, one credential-bearing gateway, independently disposable voice drivers and tokenless per-device playback workers. Parent/frontend remain PCM-free. Ordered voice negotiation, REST/state-counter reconciliation, canceled-join tombstones and bounded pending work fence stale events. Per-room cancellation does not restart peers. Ambiguous cleanup retains its reservation while the gateway epoch remains active. A whole-gateway reset stops its Discord cohort, reports unconfirmed remote departure honestly and requires fresh membership reconciliation on explicit reconnect; local capture/playback remain independent. The old combined engine owner is retired.

Version-4 preferences migrate earlier setup without changing protected credentials. Restore setup reopens saved recording inputs; application cards wait for explicit Capture against their exact saved process identity. All outputs restore disconnected/stopped. No executable-name/PID reuse, default microphone/device or alternate-room fallback is allowed. Source mute removes its contribution from the mix while its post-gain meter continues; it does not suppress original application playback. The owner's unused-endpoint routing workaround remains an OS choice, and a custom driver is postponed.

The actual approved On Air prototype remains the visual authority.
