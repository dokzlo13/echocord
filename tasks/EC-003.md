# EC-003 Prove isolated capture to Discord

Depends on EC-002 and EC-008. Audio worker a1 on `agent/EC-003-a1`, worktree `.worktrees/EC-003-a1`. Exclusive writes: `crates/core/src/audio.rs`, `crates/core/tests/audio*`, and this task record. Coordinator owns manifests, lockfiles, lib.rs exports, and shared model types. Live Discord session ownership is now EC-010, OS process ownership EC-009, shell/UI integration EC-005.

Module API: `enumerate_sources() -> Result<Vec<model::RecordingSource>, model::AppError>` and `start_capture(source_id: &str) -> Result<CaptureSession, model::AppError>` on Windows. `CaptureSession` exposes `pub input: LivePcm` and `pub control: CaptureControl`. LivePcm implements Read + Seek + Symphonia MediaSource + Send + Sync. CaptureControl is Clone and provides `stop()`, `set_output(volume_percent: u8, muted: bool)`, and `snapshot() -> model::Capture`. Capture begins only on explicit start. Use stable CPAL IDs, no default/name fallback. Preserve complete stereo frames and enforce an explicit supported 48 kHz capture format for this first slice. Source failure is observable in the capture snapshot.

Portable queue/PCM tests must cover short/fragmented reads, silence/resume, cancellation, bounded age and memory, overflow/alignment, mute draining, and skewed producer/consumer pacing. Native capture code is target-gated. Unit tests inside audio.rs are appropriate; use a temporary local lib.rs export for validation but do not commit shared-file edits. Coordinate any API changes before EC-010 consumes them.

Acceptance: selected VB-Cable recording endpoint → existing bot → selected server voice channel, with no local monitoring or capture of Discord playback. Verify actual PCM feeding, supported formats, silence/resume, stereo, mute/volume, stable queue age, and DAVE behavior when participants join/leave. Measure provisional delay targets rather than assume them.

Token enters through a local secret mechanism, never source, task notes, logs, or agent prompts. Ensure another client is not simultaneously using the same bot for the test. Live test timing needs coordination with the tester.
