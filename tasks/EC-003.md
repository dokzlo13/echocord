## Implementation checkpoint

The assigned worktree and branch were verified before implementation. The initial implementation changed only `crates/core/src/audio.rs` and this task record. Shared exports, manifests, lockfiles, and model types remain coordinator-owned. Task completion still requires coordinator integration and the native/live acceptance work below.

Implemented the agreed `enumerate_sources` / `start_capture` / `CaptureSession { input, control }` API. `CaptureControl` is cloneable and supports idempotent stop, output volume/mute, and the existing `model::Capture` snapshot. `LivePcm` implements Read, Seek, MediaSource, Send, and Sync; it is nonseekable with unknown length and accepts a position query only. Non-Windows capture calls return an explicit error. Consumers should use `RawAdapter::new(session.input, 48_000, 2)`.

Windows capture enumerates WASAPI recording endpoints and matches the explicitly supplied CPAL `DeviceId`; no default device, friendly-name lookup, playback loopback, or automatic input selection. Configuration requires a supported 48 kHz mono or stereo format, preferring stereo and then f32. Supported sample types are i8/i16/i32/i64, u8/u16/u32/u64, and f32/f64, converted directly on callback slices; mono is duplicated to stereo. Unsupported rates/layouts/formats return a visible start error. Terminal callback failures become Missing/Error snapshots; a late error cannot replace stop or the first failure. Xrun/discontinuity notifications are counted separately and remain nonterminal. Raw backend errors and device identifiers are not included in error messages.

Queue and reader policies are initial engineering bounds, not measured latency results:

- Fixed SPSC storage for 1,920 complete stereo frames (40 ms at 48 kHz), using rtrb. Overflow rejects whole incoming frames. The consumer alone removes queued frames, with bounded discard work.
- Frames older than 40 ms since callback exposure are discarded at handoff. Fragmented callback input retains the first sample's age and mute generation. One already-started 8-byte output frame is completed across fragmented byte reads to preserve valid f32/stereo alignment.
- Each read returns at most 240 frames / 1,920 bytes. A 5 ms clock budget applies to audio and synthesized silence, including repeated refills by Symphonia. Deadlines advance from the previous deadline to avoid accumulating wakeup oversleep; lateness exceeding 5 ms resets the anchor to now. At most two new quanta can be granted at one clock instant, plus any bounded remainder of an already granted quantum. The reader cannot accumulate unlimited credit when consumption pauses; waits check cancellation at intervals of at most 2 ms of requested sleep.
- Starvation remains valid input and returns paced silence. Only terminal stop returns EOF; capture failures return a terminal I/O error. Mute drains or invalidates queued audio, and callbacks meter input before output gain even while muted. Every mute transition invalidates older frames, including mute/unmute with no intervening read.
- Callback code performs conversion, bounded queue operations, and atomic telemetry only: no locks, logging, network/UI calls, or dynamic sample allocation. Reader Sync uses a mutex wrapper around the non-Sync consumer, accessed exclusively via `get_mut`; sample transfer never locks. Stream destruction occurs outside callbacks.

## Native-validation helper follow-up

The coordinator integrated the audio module and its export in `c95cf4e`; that checkpoint was merged into the verified EC-003 worktree before this follow-up. This follow-up changes only `crates/core/src/bin/capture-probe.rs` and this task record. PCM, shared exports, dependencies, and model types are unchanged.

`capture-probe --list` prints the recording-descriptor array as JSON. This explicit mode includes endpoint IDs/names and is for caller-owned private redirection. No arguments, an unknown mode, missing ID, or extra arguments return generic usage without echoing supplied values. `--help` opens nothing. `--source-id ID` accepts exactly one caller-selected ID, without default selection or a name fallback.

The selected-capture probe runs 50 live 20 ms PCM blocks (one nominal second), accepts silence, verifies complete stereo f32 frames and finite samples within the supported range, and requires an observed native callback. It measures every short Read call and each 20 ms block fill with `Instant`, reporting min/p50/p95/max times, total wall time versus nominal PCM duration, and fills exceeding 20 ms. Timings are observations with no pass/fail performance threshold; slow pacing remains visible in a functionally successful report.

After a measured 25 ms consumer pause, it records actual queue occupancy, mutes output, validates five PCM blocks of zero output and an empty queue, stops capture, checks EOF twice and Stopped/zero-queue state, drops the first session, and reopens the exact same supplied ID for ten live blocks before stopping again. The JSON summary includes only generic frame/callback/queue counters, local timings, format constants, and check results. It does not include samples, descriptors, IDs, names, meter values, or raw backend messages. Error cleanup stops the capture handle. Native stop can join a driver thread, so the caller's independent process deadline still applies.

Build and run interface (the coordinator supplies the selected ID privately and creates the ignored output directory):

```sh
cargo xwin build --locked -j2 --target x86_64-pc-windows-msvc --target-dir target -p echocord-core --bin capture-probe
target/x86_64-pc-windows-msvc/debug/capture-probe.exe --list > .trash/capture-probe/sources.json
target/x86_64-pc-windows-msvc/debug/capture-probe.exe --source-id '<explicit-recording-device-id>' > .trash/capture-probe/result.json
```

The helper's timing boundary is local PCM Read completion. It does not measure callback-to-Discord pipeline delay, hardware sample age, listener delay, or end-to-end latency. An approximately 5 ms initial read credit and per-block validation overhead can affect total wall-minus-nominal time. The occupancy before mute is reported rather than assumed nonzero; if it is zero, that run does not establish draining of preexisting captured audio. Counts of nonzero/differing-channel frames do not prove audible isolation or a specific stereo source pattern.

## Independent-review corrections

The helper was already checkpointed in `f36a69f`. The coordinator's integrated runtime/UI checkpoint was merged before these corrections. This correction changes `audio.rs`, its unit regressions, and this task record only; the helper source, shared model/TypeScript shapes, exports, and dependencies are unchanged.

- P1: CPAL WASAPI emits `ErrorKind::Xrun` on buffer discontinuity and continues capture. The callback now records a nonterminal event and allows subsequent frames. Additive `CaptureControl::xrun_events() -> u64` exposes the event count independently of `model::Capture`; no unknown number of lost frames is added to `dropped_frames` or other frame counts. The Windows regression calls the same error-dispatch function as the native callback, verifies later stereo input, and separately verifies terminal device loss.
- P1: Terminal failure now uses the pinned standard library's atomic `try_update` CAS retry operation (the current name for `fetch_update`) over the observed Opening/Running state. A promotion between observation and update is retried, while Stop or the first terminal failure is preserved. A deterministic observer injects Opening → Running immediately before the attempted CAS; companion interleavings inject stop and a competing first failure. The production observer is a no-op with no locks or allocation.
- P2: Normal 5 ms grants advance from the previous deadline. Small wakeup oversleeps no longer accumulate into an artificial sample-rate slowdown. Catch-up is limited to one quantum of lateness (two newly granted quanta at a fixed clock instant); larger stalls reset to now and cannot accumulate a long silence burst. First read starts its timeline explicitly rather than treating native open time as pacing credit. The original per-read limit, age bound, terminal cancellation, stereo staging, and mute generations are retained.

Eight added regressions cover Xrun continuation, actual Windows callback classification, startup promotion, concurrent terminal outcomes, 200 µs oversleep across 2,000 grants, actual Symphonia refill/20 ms packet cadence under oversleep, bounded catch-up, and cancellation after a larger stall. The fake-clock oversleep bounds are algorithm evidence, not measurements of the Windows scheduler.
