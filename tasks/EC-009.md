# EC-009 Windows engine-process ownership

Depends on EC-008. Process worker a1 on `agent/EC-009-a1` at `.worktrees/EC-009-a1`. Exclusive writes: `crates/core/src/process.rs`, `crates/core/src/bin/process-probe.rs`, optional `crates/core/tests/process*`, and this task. Coordinator owns Cargo/lib.rs and build scripts. No credentials or Discord needed.

Implement a small owned Windows process abstraction with creation-time job assignment and kill-on-close, redirected stdin/stdout/stderr, only required inherited handles, exact executable launch without a shell, no visible console, bounded waiting, and reliable RAII cleanup. Use stable Rust and windows-sys; do not require nightly. Job handle must not be inherited. Follow REVIEW.md.

Agreed Windows API: `EngineProcess::spawn(executable: &Path, args: &[OsString]) -> io::Result<Self>`, `take_stdin/take_stdout/take_stderr(&mut self) -> Option<std::fs::File>`, `id() -> u32`, `try_wait(&mut self) -> io::Result<Option<u32>>`, `terminate(&mut self) -> io::Result<()>`, `wait_timeout(&mut self, Duration) -> io::Result<Option<u32>>`. Exit code is u32. Dropping ownership closes the kill-on-close job; callers still explicitly observe exit for user-visible completion. Document Send safety of owned handles if required.

Acceptance: Windows self-contained supervision probe covers ignoring stop, blocked stdin, concurrent stdout/stderr flooding, exit during initialization, parent death during startup/active state, and normal next launch after exit. Assert no orphan process after ownership is lost. Raw logs/private PID paths stay under `.trash/`. Public output uses generic outcomes. Module may use a temporary lib.rs export for local validation but must not commit shared-file edits.
