Depends on EC-008. Process worker a1 on `agent/EC-009-a1` at `.worktrees/EC-009-a1`. Exclusive writes: `crates/core/src/process.rs`, `crates/core/src/bin/process-probe.rs`, optional `crates/core/tests/process*`, and this task. Coordinator owns Cargo/lib.rs and build scripts. No credentials or Discord needed.

Implement a small owned Windows process abstraction with creation-time job assignment and kill-on-close, redirected stdin/stdout/stderr, only required inherited handles, exact executable launch without a shell, no visible console, bounded waiting, and reliable RAII cleanup. Use stable Rust and windows-sys; do not require nightly. Job handle must not be inherited. Follow REVIEW.md.

Agreed Windows API: `EngineProcess::spawn(executable: &Path, args: &[OsString]) -> io::Result<Self>`, `take_stdin/take_stdout/take_stderr(&mut self) -> Option<std::fs::File>`, `id() -> u32`, `try_wait(&mut self) -> io::Result<Option<u32>>`, `terminate(&mut self) -> io::Result<()>`, `wait_timeout(&mut self, Duration) -> io::Result<Option<u32>>`. Exit code is u32. Dropping ownership closes the kill-on-close job; callers still explicitly observe exit for user-visible completion. Document Send safety of owned handles if required.

Acceptance: Windows self-contained supervision probe covers ignoring stop, blocked stdin, concurrent stdout/stderr flooding, exit during initialization, parent death during startup/active state, and normal next launch after exit. Assert no orphan process after ownership is lost. Raw logs/private PID paths stay under `.trash/`. Public output uses generic outcomes. Module may use a temporary lib.rs export for local validation but must not commit shared-file edits.

## Implementation and integration handoff

The agreed API is implemented in process.rs using Rust 1.99.0, windows-sys 0.61.2 from the lockfile, raw WinAPI, and RAII-owned handles. Job membership and the three-handle inheritance whitelist are supplied together to CreateProcessW. The fresh unnamed job is not inheritable, allows no breakaway, and closes before the remaining owned handles. Attribute storage is aligned and retains its borrowed handle arrays through creation and list destruction. Successful creation has no subsequent fallible setup. Error paths release all prepared handles and preserve the original Win32 error.

The exact absolute executable path is passed separately from the mutable UTF-16 command line. CRT/Rust argument quoting preserves empty arguments, embedded quotes, trailing backslashes, Unicode, and unpaired surrogates. NULs, relative executable paths, and oversized command lines fail before launch. STARTF_USESTDHANDLES redirects all three pipes, including for a Windows GUI subsystem executable. CREATE_NO_WINDOW suppresses a console. Parent copies of child pipe ends and the initial thread handle close immediately.

The probe imports process.rs directly. No temporary lib.rs changes, additional Cargo features, or changes to manifests/lockfiles are part of the worker implementation. The coordinator's main checkpoint was merged before final validation. Integration needs the coordinator-owned `#[cfg(windows)] pub mod process;` export in crates/core/src/lib.rs and session-controller use of the agreed API. Independent review and combined integration checks remain with the coordinator; this worker handoff does not mark the task done.

## API limits and next action

Requires Windows 10 or later for creation-time job-list support; incompatible job nesting or creation failures return an error rather than weakening ownership. Spawn inherits the parent's environment and working directory and proves creation, not successful initialization. The engine contract prohibits subprocesses; the job still owns descendants if that contract is violated.

`terminate` requests asynchronous forced exit with code 1. `wait_timeout` and `try_wait` confirm exit using the owned process handle and return the actual u32 code; a genuine 259 exit is supported. Drop initiates kill-on-close termination but does not synchronously confirm it. The session controller must retain ownership, observe exit, and keep cleanup failure explicit before allowing another connection. Taken Files are synchronous: drain stdout and stderr concurrently and keep stdin writing independent of the stop deadline. Pipe EOF or a Stopped message cannot replace exit observation. Windows waits round sub-millisecond durations up and split large durations into finite waits; scheduling/kernel I/O can still delay completion. The probe covers synthetic lifecycle behavior, not real Tauri integration, audio, or Discord.

Next: independent ownership/race review, add the coordinator-owned module export, integrate the session controller, and run combined native application checks before task closure.
