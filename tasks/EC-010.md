# EC-010 Session controller and Discord engine

Depends on EC-008. Runtime worker a1 on `agent/EC-010-a1` at `.worktrees/EC-010-a1`. Exclusive writes: `crates/core/src/controller.rs`, `crates/core/src/engine.rs`, `crates/core/src/protocol.rs`, tests scoped to those modules, and this task. Coordinator owns Cargo/lib.rs/model and shell. Integrate agreed audio/process APIs from EC-003/009 before final Windows verification.

Use the Rust-owned model contract. Parent controller owns selection, configuration loading, REST-only discovery, session generation, output preferences, launch cooldown, child supervision, and authoritative snapshots. Child mode owns CPAL + Songbird + Serenity gateway and processes typed bounded JSON lines. No token in command-line arguments, frontend types, debug formatting, or protocol logs; initial backend message can identify a private token file. No child starts capture or gateway work before valid initialization. No automatic initial voice connection or crash respawn.

Public parent API: `Controller::spawn(config: ControllerConfig) -> Controller`, Clone handle; `snapshot() -> model::ControlSnapshot`, `subscribe() -> tokio::sync::watch::Receiver<model::ControlSnapshot>`, `dispatch(model::ControlCommand) -> async Result<(), model::AppError>`, `shutdown() -> async Result<(), model::AppError>`. ControllerConfig carries `executable: PathBuf`, `token_file: Option<PathBuf>`, `settings_file: Option<PathBuf>`. Private values must not enter snapshots. Shell uses snapshots/commands, not engine handles.

Child API: `engine::run_worker() -> async Result<(), model::AppError>` reading redirected standard handles; protocol parser bounds line lengths and validates version/generation/sequence. Its diagnostics must be sanitized. Parent starts child with internal `--engine-worker` mode only, no secret CLI arguments. Parent drains both output pipes, bounds/coalesces control/telemetry, and rejects stale status after cancellation. Disconnect deadline runs independently of writes, ends with termination if needed, and requires observed exit before reporting Disconnected. Stop/EOF is terminal. Keep Connect disabled on incomplete cleanup. Native supervision lives in EC-009.

Inside the worker: attach live PCM only to the current session after join; finite Songbird retries and application deadline, no extra looping join attempts. Device loss stops output, retries only the same stable endpoint for a finite grace, then surfaces failure. Permission/removal/unexpected channel move is terminal. Silence is valid. Mute/volume preserve capture draining and user selection. Respect parent launch cooldown and Discord start-limit data. Include portable state/protocol regression tests, including stale callbacks, disconnect during join/recovery, failure/cleanup states, and secret-safe errors.

Production UI waits for EC-007 evaluation. This worker does not perform live Discord tests or read private project credentials; coordinator runs authorized verification later. Use temporary lib.rs exports for local tests if needed; do not commit shared-file changes. Request dependencies/model changes from coordinator rather than editing shared ownership.
