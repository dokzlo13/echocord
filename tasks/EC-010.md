## Implementation and handoff

Portable parent actor, private protocol, and Windows child implementation are present in the scoped modules. The fixed Controller/ControllerConfig and run_worker APIs are implemented without additional dependency or model requests. Parent selection/preferences/discovery remain separate from gateway/capture work. The supervisor uses the EC-009 API on Windows, drains both pipes concurrently, coalesces output and meter data, publishes meters at most 10 Hz, and observes process exit before completing Disconnect. Deadline enforcement does not wait for stdin. Cleanup failure remains locked; crash exit never triggers respawn.

The protocol bounds JSON lines to 8192 bytes, requires the pinned version, nonzero generation, and increasing sequence, rejects duplicate initialization, and exposes only fixed diagnostic codes. Config/Init debug formatting hides private paths; token reads are bounded and errors never include payloads or paths. Preferences contain selection and output only.

Main was merged through c95cf4e, including the actual EC-003 audio and EC-009 process modules and coordinator-owned exports. Child capture uses the real LivePcm through Songbird RawAdapter at 48 kHz stereo and CaptureControl for output changes. Capture attaches only after the one initial join and current-channel/cancellation checks; cancellation releases capture before gateway cleanup. Missing-device retries retain the exact source ID. Capture errors, permission rejection, selected guild/channel removal, and unexpected bot movement terminate the session. Gateway/guild recovery conditions are independent, and repeated notifications cannot extend an existing deadline.

Current implementation budgets are five seconds between worker launches, fresh REST gateway-start allowance before each launch, 750 milliseconds for graceful stop followed by three seconds for forced-exit observation, a 45-second parent connection deadline, and a 40-second parent recovery deadline. Child startup join is bounded to 35 seconds after client creation, gateway/guild recovery to 35 seconds, and device-return grace to 30 seconds with one-second attempts. Songbird uses three retries with one-second spacing and five-second driver timeouts, without an application rejoin loop. These are implementation defaults, not measured latency or native scheduling guarantees. Coordinator shortened the original three-second graceful allowance to the reviewed first-build policy; exit confirmation remains mandatory.
