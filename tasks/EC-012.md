## Accepted behavior and diagnosis

The controller handled preflight completion by synchronously spawning its worker. On Windows this calls `CreateProcessW` on the controller actor; a slow executable launch therefore delays every subsequent actor command and publication. Dispatch in the shell is already asynchronous. Inspection establishes the blocking path; no claim is made that a Windows trace measured the complete reported stall.

Process creation now runs on the blocking pool. The actor registers its control mailbox first, so mute, volume and Cancel can be acknowledged while creation is pending. Cancellation before the writer commits initialization suppresses Init; the child stays owned and uses the original 750 ms stop grace. Route selection/reconnect remains locked until actual exit, or until process creation fails without creating a child. The parent still owns shell integration and exit policy.

The approved Rust/generated TypeScript contract uses `Connecting { stage }` with `checking`, `preflight`, `gateway`, `join`, and `capture`. Stages represent actual local configuration checks, REST preflight, gateway startup, voice handshake, and capture opening. No percentage or timer simulates progress. Stage events are generation scoped, monotonic within connection, ignored after cancellation/connection, and cannot extend the absolute connection deadline. Cancel aborts in-flight preflight.

REST catalog discovery adds optional `iconUrl` using Serenity's Discord CDN formatter, optional `categoryName` by resolving channel parent IDs against the same REST catalog, and the channel's actual `position`. Voice channels are sorted by position and ID. No gateway or voice member list is used for discovery.

## Private configuration delivery

`Controller::configure_token(token: String) -> async Result<(), AppError>` is implemented through a private request without serialization or Debug. It rejects live/pending/cleanup sessions and overlapping configuration requests, checks token syntax and separation from the preferences file, marks the bot Checking, and prevents Connect while testing. It invalidates older catalog callbacks. REST verifies that the credential belongs to a bot; only successful validation reaches `storage::save_token`. Encryption/write work runs on the blocking pool, and success is acknowledged only after saving actually completes. Validation/save failure restores the previous bot/discovery state; an interrupted older discovery is restarted against the unchanged saved configuration. Errors are sanitized and no token enters the shared snapshot, command contract, or logs.

Missing token paths specifically classified as filesystem NotFound start Unconfigured with idle discovery; an existing corrupt/unreadable file remains an error. Preferences creates its parent directory when a save is requested, allowing output changes before first token setup. File equality and symlink aliases cannot make configuration overwrite preferences. A late engine initialization also takes the newest mute/volume settings from its mailbox rather than the output state captured before process creation.

## Independent review follow-up

The configuration delivery is integrated as `93c6acb`. Independent review found two races, addressed in a scoped controller/test follow-up:

- The writer now checks cancellation and consumes the latest output inside the executing blocking task, immediately before its Init commitment. That decision shares the mailbox lock with Stop; pipe I/O runs after releasing the lock. Cancellation while the writer is queued emits no Init. Cancellation after commitment uses the existing Stop/supervisor path and does not wait on a pipe lock.
- Configuration validation and saving share a private mutex-protected phase. Shutdown cancels/aborts only validation. Once saving is committed, even if its blocking task is still queued, both the configuration reply and graceful shutdown remain pending until the actual save result is received. Completion during shutdown does not start catalog discovery. The shell retains its separate three-second Quit fallback; no OS disk operation is claimed to be cancellable.

Regressions occupy the sole thread in a synthetic blocking pool before queuing a writer, then verify that Cancel emits zero bytes and output changes reach the eventual Init. The sink also triggers Stop during write to prove that pipe I/O holds no mailbox lock. The blocked-save regression requests Shutdown before releasing storage and verifies that both replies remain pending. A stalled-validation regression verifies prompt shutdown and that cancellation prevents a later save commitment.
