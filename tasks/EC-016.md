## Implementation handoff

The four agreed APIs are implemented in `crates/core/src/storage.rs`. `default_data_dir` uses `ProjectDirs::from("", "", "Echocord").data_local_dir()` without creating directories. Callers supply explicit save/load paths to override it. The file family marker is `ECHOCORD-TOKEN` followed by NUL; version 1 is one byte, followed by a little-endian four-byte ciphertext length and the DPAPI blob. Tokens are limited to 4096 bytes; complete encrypted files to 16384 bytes. Empty tokens, whitespace/control characters, malformed lengths, unknown versions, and plaintext files are rejected. `is_encrypted` identifies the family even for unknown versions and truncated envelopes with the complete marker, so adapters must not treat a failed load as plaintext.

Windows protection uses current-user DPAPI with `CRYPTPROTECT_UI_FORBIDDEN`, null prompt/description pointers, and fixed application/version entropy. Decryption validates UTF-8 and token syntax. DPAPI allocations are cleared and released with `LocalFree`; the returned token remains an ordinary caller-owned `String`. Save encrypts before touching disk, writes and flushes a newly created sibling file, then uses `MoveFileExW` with replacement/write-through flags and no cross-volume copy fallback. Failure cleanup removes only that invocation's temporary file. No credential values, input paths, or native error payloads enter errors. Non-Windows save/load return a configuration error without touching token paths.

The scoped `storage-probe` includes the module directly, allowing tests without any shared `lib.rs` edit. Its Windows run requires an explicit absolute directory under `.trash`, creates only a unique synthetic child, and removes only that child after success. No live credentials, voice calls, or application-default storage writes are involved.

Validation: module/probe rustfmt; `cargo test --locked -j 2 -p echocord-core --bin storage-probe` (four portable tests passed); `cargo clippy --locked -j 2 -p echocord-core --bin storage-probe -- -D warnings` passed. Windows release cross-compilation and Clippy passed with `-j 2`, the MSVC target, and dynamic CRT. `cargo xwin test --locked --release -j 2 --target x86_64-pc-windows-msvc -p echocord-core --bin storage-probe --no-run` produced a test executable; running it on Windows passed four tests, including rejection of an otherwise valid DPAPI blob protected with a different entropy domain. The synthetic native probe passed roundtrip/replacement, the 4096-byte token boundary, corruption/wrong blobs, truncated/unknown-version/inconsistent-length/trailing/oversized/plaintext files, missing files, error redaction, and absence of plaintext in saved files. A destination locked without delete sharing rejected replacement, preserved the existing ciphertext byte for byte, and left no temporary files. The probe also checked failure cleanup when the destination was a directory. All filesystem fixtures used an explicit ignored `.trash` directory; raw logs remain ignored.

The worker branch is based directly on the parent's unchanged dependency commit. Parent still owns module export, protocol detection/loading, and controller/shell integration. Coordinator review/integration and combined checks remain required before task closure. No temporary `lib.rs` export was needed or committed.
