# EC-017 Driver-free application capture

Next major feature after the bounded EC-021 polish pass. Owner unassigned. Dependencies: EC-014 research and an explicit reviewed source-selection design before production UI integration. Read docs/CAPTURE.md and retain the working recording-input path.

Build one narrow Rust Windows process-tree capture experiment, with normal-user operation, source/build/tooling in WSL, and explicit synthetic test sources. Prefer the researched WASAPI wrapper after validating its pinned API. Capture only the included process tree; never silently widen to desktop/exclusion capture. Keep PCM within the engine; use bounded buffers, correct silence/packet flags, and observed cleanup. No credentials or Discord connection is needed to establish this boundary.

Acceptance evidence: selected/unselected signal isolation; browser process-tree scope; supported format and stereo behavior; silence/resume; source exit/restart and device changes; cancellation and queue age. Separately test application, audio-session and endpoint mute against both captured signal and local audibility. Do not promise independent local suppression until measured. Store raw recordings/host details under ignored .trash and commit only generic findings.

After the experiment, review a source-selection flow and integrate one testable source type. Multiple-source clock alignment, one common mix with multiple destinations, and a virtual-device driver remain separate work. Keep the Discord one-bot-per-guild constraint in the destination design. Do not add inactive placeholder controls to the production UI.

## Intended feature delivery

The experiment is a risk-reduction milestone, not the final feature. Deliver a reviewed source-selection flow and a working application/process-tree capture path that avoids a virtual cable where supported, while retaining explicit recording-device capture. Check browser process-tree scope and communicate selection boundaries; never imply per-tab isolation without evidence.

Assess desktop/playback-device loopback as another explicit source mode, with clear whole-endpoint capture scope and protection against accidentally recapturing the Discord call. Separately establish whether original local playback can be suppressed without suppressing captured samples; report limitations honestly. An owned virtual endpoint remains a separate driver project if pursued, not an assumed prerequisite for this feature.

Integrate and validate the chosen native capture adapter in the existing engine and UI, then provide a real-user testable build. Review design before the source-picker extension and keep the unrelated mixing/fan-out implementation in EC-020.
