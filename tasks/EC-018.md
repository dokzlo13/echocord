## Implementation contract

`outputLevelDbfs` is a nullable scalar peak over actual complete stereo frames handed to the native reader after gain/mute, before Discord. Hold a peak for at most 200 ms; silence/starvation and expired observations use -96 dBFS. Initial/opening/stopped/missing/error states are null. Running mute immediately reports the silence floor; unmute requires a handoff in the new mute generation. Gain changes require an observation matching the current settings. Capture `levelDbfs` stays pre-gain and independent of mute. Both fields are finite/clamped at the protocol boundary.

The contract is available separately for concurrent frontend implementation. Native observations and regression evidence follow before worker handoff; the coordinator owns integration and completion.

## Worker implementation and portable evidence

The PCM reader tracks complete handed-off stereo frames, preserving existing pacing, queue rejection and the one-frame partial-read staging exception. Peak freshness starts at the first byte of that frame so completing an old fragment cannot renew it. Each read publishes one scalar observation through a fixed set of atomics; snapshots make one bounded attempt and return null on a concurrent publication. Capture callbacks do no additional work. Observations carry the existing output settings and mute generation; volume changes do not change the audio queue generation or discard queued frames.
