# EC-019 Isolated control and telemetry subscriptions

Owner adapter worker a1; .worktrees/EC-019-a1, agent/EC-019-a1. Scope ui/src/adapter.ts, nativeAdapter.ts, ui/tests/adapter.spec.ts and this task. Exclude App/components/styles/fixtures/generated.ts. Coordinator owns shell; UI worker consumes agreed API.

Preserve existing getSnapshot/subscribe control semantics while preventing meter-only snapshot revisions from publishing new control ViewState. Maintain a separate latest full snapshot/revision for ordering and apply/cancel correctness. Changes to capture phase/message, connections, configuration, selections, output and catalogs must still notify controls. Telemetry fields alone must not rerender root/list/settings. Avoid retaining unbounded history.

Expose getTelemetrySnapshot()/subscribeTelemetry() with cached {sessionId:number, sourceId:string|null, capture:Capture|null, visible:boolean}. EC-018 adds Capture.outputLevelDbfs:number|null. UI Meter components consume these only. No React component work here. Define/implement optional Transport.getVisible()->Promise<boolean>, listenVisibility(receive:boolean)->Promise<unsubscribe>; native names get_visibility and echocord://visibility. Listener before initial visibility read; reject stale generations/races, clean up on disposal, default true for fixture transports lacking native visibility. Native hidden state pauses notifications/presentation but retains freshest observation; visible return publishes latest. UI also respects document visibility.

Test unchanged control identity/listener count under telemetry bursts, control-state/capture-error transitions, stale revisions/disposal, hidden/resume behavior, and existing route/config/volume regressions. No user token or real services. Read project instructions and manually open Playwright skill for browser test work; no context launcher rerun. Generic commits, private evidence ignored.
