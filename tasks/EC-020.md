# EC-020 Destination fan-out and shared-mix extensions

Next major design topic after feedback on the mixing build. Owner unassigned. EC-023 implements the reviewed shared native mix; fan-out implementation still depends on a focused destination architecture/design review. Read BRIEF, CAPTURE, QUALITY and the accepted UI design before implementation.

Goal: multiple explicitly selected sources feed one common mix, then the same mix feeds selected destinations. No per-source/per-destination routing matrix or advanced DSP. Keep source isolation and WSL development; do not start with a virtual driver.

The first increment is delivered by EC-023/024: supported input formats feed a fixed 48 kHz native timeline, per-source gain/mute and health, unity summation with hard clipping, and one independently controlled Discord destination. The bounded shared ring supports fresh independent readers. The accepted UI uses immediate targeted card edits; global draft/apply and a shared master bar are superseded.

Next, review independent output readers/workers, credential ownership, destination limits and UI capacity. Fan out the common PCM without allowing a slow output to stall capture or other outputs. Retain per-destination gain/mute, explicit connection and health, and observed teardown. Review failure/cancellation ownership before implementation and preserve the working mixed Discord route.

One bot identity supports one voice channel per guild; simultaneous same-guild destinations require separate bot identities. Validate any local playback destination independently. Suppressing original application playback is separate from muting Echocord monitoring: EC-017 measured session mute also suppressing captured samples, so it ships no independent local suppression. An owned virtual endpoint remains a separate driver/signing/admin project, not a shortcut assumed by this task.

Acceptance: distinguishable-source isolation and correct mix, bounded queues/age across skewed clocks, silence/resume, source removal, per-output failure/slow-consumer containment, authoritative route changes, mute/cancel behavior, and no capture fallback. Measure actual native behavior and then run the longer EC-006 session acceptance. Record sanitized results only; raw recordings, identities and host details remain private.

Remaining work is planning only: multiple-source mixing exists; destination fan-out and an owned driver do not. Independent long-session clock drift and output backpressure measurements remain explicit acceptance work.
