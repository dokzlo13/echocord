# EC-020 Shared mix and destination fan-out

Deferred beyond the current UI session. Owner unassigned. Depends on capture/source evidence in EC-017 and a reviewed mixer architecture/design. Read BRIEF, CAPTURE, QUALITY and the accepted UI design before implementation.

Goal: multiple explicitly selected sources feed one common mix, then the same mix feeds selected destinations. No per-source/per-destination routing matrix or advanced DSP. Keep source isolation and WSL development; do not start with a virtual driver.

Plan separate bounded increments: (1) normalize supported input formats and align independent source clocks on one bounded native mix timeline; establish clipping/headroom policy and per-source diagnostics; (2) fan out common PCM through independent bounded destination queues without letting one slow output stall capture/other outputs; (3) add explicit draft/apply UX, shared master/mute and individual destination identity/health. Review failure/cancellation ownership at each increment. Preserve the currently working one-source/Discord route throughout.

One bot identity supports one voice channel per guild; simultaneous same-guild destinations require separate bot identities. Validate any local playback destination independently. Suppressing the original application's local sound is separate from muting Echocord monitoring, and remains an EC-017 experiment. An owned virtual endpoint is a separate driver/signing/admin project, not a shortcut assumed by this task.

Acceptance: distinguishable-source isolation and correct mix, bounded queues/age across skewed clocks, silence/resume, source removal, per-output failure/slow-consumer containment, authoritative route changes, mute/cancel behavior, and no capture fallback. Measure actual native behavior and then run the longer EC-006 session acceptance. Record sanitized results only; raw recordings, identities and host details remain private.

This task is planning only; no mixing, fan-out, new capture or driver implementation was started in the UI session.
