## Attempt a1 reviewed decisions and implementation

The owner corrected the picker scope: the previous panels occupied too much of the compact window. The coordinator and independent reviewer accepted contextual, nonmodal source/room popovers after rendered comparison. They use content-sized height, a 344 px width cap and a 368 px height cap, with placement reserved above transport. Only selection lists scroll. Search receives initial focus; Escape/close restores the opener; keyboard navigation reaches transport; an outside Mute/Stop click dismisses and executes the action. Bot settings and longer audio details retain their existing sheets.

Primary research used Exa to inspect [Windows dialogs/flyouts](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/dialogs-and-flyouts/), [Windows flyout dismissal](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/dialogs-and-flyouts/flyouts), [Mantine Popover](https://mantine.dev/core/popover/), and [W3C grouped listbox guidance](https://www.w3.org/WAI/ARIA/apg/patterns/listbox/examples/listbox-grouped/). Windows guidance supports lightweight contextual selection; Mantine supplies placement and trigger semantics. The implementation deliberately keeps native buttons and nonmodal transport access instead of claiming a custom listbox interaction model. [OBS device selection](https://obsproject.com/kb/audio-sources) and [Kenku external inputs](https://www.kenku.fm/docs/external-inputs) provide shipped audio-tool context. A narrower full-height panel still covered most of the window height; a separate native picker window introduced ownership, focus and placement work without an established need.

Server headings, indented categories and room rows now have distinct hierarchy. Search retains server/category context and uses more compact group spacing. Current/Queued markers remain explicit; accessible descriptions identify room parents. Queued route entries label Input, Server and Room with confirmed and proposed values. Unchanged source entries disappear after partial source confirmation, while destination context remains visible. Compact states preserve the current route, readings and Apply/Discard/recovery/transport actions; longer names retain full text in pickers and value tooltips. The volume scale endpoint omits its redundant percent sign to leave a clear gap beside the mix readout.

Meter diagnosis found direct bar replacement at each approximately 10 Hz observation, with no interpolation from the existing 20 Hz presentation cap and a separate native 200 ms output peak hold. The reviewed implementation keeps those cadences unchanged and adds CSS-only transform interpolation: 80 ms attack and 180 ms release. Numeric text and the semantic meter always use the exact latest native observation. Null/non-running readings, session/source changes, initial/resumed visibility and confirmed output mute/zero gain snap to the current observation. The output-only reset leaves pre-gain input activity intact. Document/native hiding cancels transitions and timers; reduced motion suppresses interpolation. No measurement history, animation loop, React telemetry state or audio-buffer IPC was added.
